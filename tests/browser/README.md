# Браузерные e2e-тесты

Проверяют то, чего не видит API: отрисовался ли график, не пуста ли вкладка,
работает ли кнопка, не перекрывает ли одна панель другую.

Все дефекты, ради которых они написаны, находились вручную — скриншотами:

| Что было | Как выглядело |
|---|---|
| Закэшированный `dashboard.js` | три разные вкладки показывали «Обзор» |
| Незакрытый `<div>` в разметке | кнопка «Загрузить» висела поверх панели Jira |
| Нагрузка писалась в одну команду | вкладка отвечала 200, но была пуста |
| Пересчёт брал доску первой команды | метрики второй считались по чужой классификации |

Общее у них одно: **API отвечал корректно**, а пользователь видел неверное.

## Запуск

```bash
pytest tests/browser              # только браузерные
pytest                            # обычные, без браузерных
```

Браузерные исключены из обычного прогона (`norecursedirs` в `pyproject.toml`):
они на порядок медленнее и требуют установленного chromium.

Первый запуск требует браузера:

```bash
playwright install chromium
```

**Не запускайте оба набора одновременно.** База одна, и браузерные тесты
меняют в ней статусы и обещания — обычные тесты в это время увидят чужие
изменения и упадут. Запускать последовательно.

## Как устроено

`conftest.py` поднимает **свой экземпляр сервиса** на свободном порту —
отдельным процессом, а не через `TestClient`. Браузеру нужен настоящий HTTP:
только так проверяется реальная отдача статики, заголовков и версионирования.

Данные — две команды с разной классификацией `qa` (у одной это работа,
у другой очередь), у каждой свой владелец, плюс администратор. Ровно та
конфигурация, на которой проявлялись найденные дефекты.

Вход передаётся заголовком `Authorization`: диалог Basic в браузере иначе
не закрыть, а поведение при этом ровно то же.

## Что проверяется

**`test_tabs.py`** — каждая вкладка открывается, рисует ожидаемое число
графиков и не роняет ошибок в консоль. Отдельно: у второй команды тоже,
вкладки не показывают одно и то же, активна ровно одна панель.

**`test_access.py`** — пользователь физически не видит чужого: ни вкладки
админки, ни названий чужих команд, ни данных по прямому запросу.

**`test_workflows.py`** — сценарии целиком: переключил статус и увидел
изменившуюся эффективность, зафиксировал обещание, сменил фильтр,
выгрузил файл.

**`test_admin.py`** — админская панель: метрики использования, создание
пользователей, выдача и отзыв доступа к командам.

## Чего они не проверяют

Внешний вид: наложения, отступы, читаемость подписей на графиках. Это
по-прежнему смотрится глазами на скриншотах — автоматизировать сравнение
изображений дороже, чем оно даёт.
